# MEMORY — 项目长期记忆

这里放**开发者视角**的东西：为什么这么做、DSH 的哪些行为是实测出来的、踩过哪些坑、还剩什么没做。
面向使用者的说明在根目录 [`README.md`](../README.md)（中文）与 [`README.en.md`](../README.en.md)（英文），
两者分工明确：README 只留"一眼看完"的部分，这里讲"为什么是这样"以及**使用细节的完整版**。

| 文件 | 内容 | 什么时候看 |
|---|---|---|
| [`FACTS.md`](FACTS.md) | **实测契约与不变量**：DSH 的私有面、文件布局、宿主行为、Slot 目录。只写亲自量过的，每条都注明证据来源 | 改代码之前；怀疑某个 API 行为时 |
| [`DECISION.md`](DECISION.md) | **设计决定与理由**：每条都写"背景 / 决定 / 理由 / 代价"；末尾还有一节**已废止的旧设计**（留着防止有人把踩过的坑重新发明一遍） | 想改现有做法之前；review 时 |
| [`DEV_LOGS.md`](DEV_LOGS.md) | **开发流水账**：按日期记录每次翻车的现象、根因、修复、验证 | 排查"这个我以前是不是遇到过"；写 issue 时 |
| [`TODOS.md`](TODOS.md) | **待办与已知缺口**：明确的未做项、已知的降级行为、可以接受但不完美的取舍 | 开始新一轮开发之前 |
| [`USAGE.md`](USAGE.md) | **使用与排错的完整版（中文）**：README 里删掉的细节都收在这里 —— 三种 shell 的安装写法、排错表、用法全流程、安全与行为说明全文、报告与备份的落盘位置、兼容性核对清单 | README 不够用时；回答用户提问、写 issue 回复时 |
| [`USAGE.en.md`](USAGE.en.md) | 上面那份的英文版（与 `USAGE.md` 内容一一对应，`README.en.md` 链到它） | 面向英文读者时 |

## 约定

1. **`FACTS.md` 只写实测过的**。读源码推断出来的结论要标 `（源码推断，未实测）`，
   并尽量补一次真机探测把它升级成实测。
2. **`DECISION.md` 是只增不改的**：推翻旧决定时**新增一条**并注明它取代了哪一条，
   而不是把旧的改掉 —— 否则以后没人知道当初为什么那么写。
3. **`DEV_LOGS.md` 按时间倒序或正序追加**，每条必须带**根因**，只写"改了什么"等于没写。
4. **`TODOS.md` 是活的**：做完就删掉或移进 `DEV_LOGS.md`，别留已完成的条目。
5. 每条事实/决定后面尽量写**是哪次真机验证**或**哪个测试**在守它，别只写结论。

## 和代码/测试的关系

- **测试是执行者，这里是理由**。`test/` 里的四个套件和 `tools/run-mutations.mjs`
  是唯一能在机器上否决改动的东西；本目录的作用是让那些断言**为什么存在**能被读懂。
- 设计文档的完整版本曾放在 `docs/DESIGN-live-move.md`，内容已按上面的分工拆进这几个文件
  （契约 → `FACTS.md`，决定 → `DECISION.md`，事故 → `DEV_LOGS.md`，缺口 → `TODOS.md`），
  那份文件已删除，避免同一件事有两个地方在写、然后慢慢对不上。
- 面向使用者的正文同理：**README 只留精简版**（结构对齐上游同类插件：编号章节 + 密集条目），
  写不下或者删掉的细节一律进 `USAGE.md`，README 里用链接指过去 —— 不许"精简"成丢失。
